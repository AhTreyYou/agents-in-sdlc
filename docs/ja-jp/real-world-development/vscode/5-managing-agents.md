GitHub Copilot をエージェントモードにすると、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ユーザーのコンピューター上で実行される作業をリアルタイムで確認できます。すべてのツール呼び出しやファイル編集が表示され、差分をインラインでレビューし、個々の変更を承認または取り消し、追加のプロンプトで会話を調整したり作業を広げたりできます。エディターを離れる必要はありません。

この演習では、次の操作を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッション中にエージェントへ指示し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中、デザインチームから追加の要望がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加したいとのことです。最初から会話をやり直すのではなく、既存のセッションに追加の作業を依頼します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案された編集などを確認できます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 の Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイル編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を取り消し、エージェントに別の方法を試させます。
4. チャット上部の **Files changed** インジケーターを開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合は、エージェントが一時停止し、**Allow** を求めます。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に、行った変更の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたので、同じ会話でライトモードの切り替え機能を追加します。同じチャットセッションを続けると、エージェントは前の作業から、変更したコンポーネント、スタイルの方針、設定したローカルストレージの使い方などのコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントがすでに行った変更を確認し、ライトモードの機能を追加します。
3. ハイコントラストのときと同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合（たとえば、切り替え UI を意図しない方法でリファクタリングする場合）は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の指示を送ります。

> [!TIP]
> 進行中のセッションに指示するほうが、最初からやり直すよりもすばやく作業できます。追加のプロンプトで変更（「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使う」）、方向の修正（「切り替えを 3 つに増やさず、ライトモードを既存の設定パネルに統合する」）、範囲の拡張（「両方の切り替えにキーボードショートカットも追加する」）を依頼できます。

## 作業対象をレビューする

変更をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントが指定したアクセシビリティのパターン（ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存）が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージングしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、指示を出しました。ファイル編集を確認して承認または取り消し、コンテキストを失わずに追加のプロンプトで作業を広げました。

このレッスンでは、次の操作を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を承認または取り消しました。
- 追加のプロンプトを使って、進行中のセッションに指示しました。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
