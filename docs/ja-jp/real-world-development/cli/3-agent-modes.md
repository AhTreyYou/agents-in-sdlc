最初に、小さな機能をプロジェクトに追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は、組織で既に使っている開発フローに沿って、適切な方法で適切なものを構築できるように設計されています。このレッスンから、エージェントを使った一般的な開発プロセスに沿って作業します。issue から新機能を作成し、コードが有効で、機能が想定どおりに動作することを確認した後、プロジェクトにマージします。

> [!NOTE]
> 機能の作業を続ける間、同じ会話とブランチを使います。通常、ファイルの種類ごとに異なるブランチや PR を使いますが、ここでは主な概念に集中できるよう、手順を簡略化します。

このレッスンでは、次の操作を行います。

- GitHub issue から新しい Copilot 会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送したブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のカタログが増えており、訪問者はカテゴリや発行者でゲームを絞り込む必要があります。バックログの issue には機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておくべき詳細があります。Plan モードで決定事項を整理し、Autopilot に範囲を定めた実装を依頼します。

## 背景

AI コーディングエージェントを開発フローに取り入れても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業しています。

1. 実装する内容を説明した issue から始めます。
2. 構築する内容を計画します。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューと継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 具体的な手順はチームや組織によって異なりますが、一般的には上記の流れに沿って進めます。

この標準的な方法を守ることで、AI が生成したコードが要件を満たし、手作業で作成したコードと同じレビューのプロセスを経るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを設定します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押してモードを切り替えます。

- **Interactive**: エージェントが変更を提案し、次に進む前にユーザーの入力を待ちます。
- **Plan**: エージェントが最初に計画を作成し、プロジェクトファイルの編集は行いません。
- **Autopilot**: エージェントがコードを書き、テストを実行し、タスクが完了するまで自律的に作業を繰り返します。

まず Plan モードで計画を確認し、その後 Autopilot で実装します。

## issue から作業を始める

フィルタリングの作業を始める前に、Codespace に戻り、リポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続行します。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルタリング用ブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべての issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトの先頭に `#7`（または同様の番号）が追加されます。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てると、Copilot に依頼する前に、機能の実装方法やタスクの進め方を決められます。複雑な作業では、時間をかけて計画することをお勧めします。Plan モードに切り替えて、Copilot に計画を作成するよう依頼します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調べて、実装に適した方法を判断し、計画を作成します。

3. 作業中に、Copilot からフィルタリング機能の動作について質問されることがあります。希望に基づいて回答してください。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールして確認します。
6. 自分の決定と合わない部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、機能を実装します。Autopilot モードを使って Copilot に作業を依頼します。

Autopilot を使うと、Copilot はタスクが完了したと判断するまで問題に取り組み、変更を繰り返します。

1. **Accept plan and build on autopilot (recommended)**、またはインストール済みのバージョンに表示される同様の項目を選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って作業を繰り返し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認するとすぐに実装が始まる場合があります。先に計画をレビューしてください。Copilot から依存関係が不足している、またはポートが競合していると報告された場合は、チェック完了とみなす前にセットアップの問題を解決してください。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同じように、マージする前にレビューします。コードを確認し、サイトを起動して問題がないことを確認しましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードにします。モード表示が **Plan** または **Autopilot** でないことを確認します。
2. `/diff` を実行し、フィルタリングの実装とテストを確認します。
3. 結果を issue と計画時の決定事項と照らし合わせます。
4. コードのレビューが終わったら <kbd>Esc</kbd> を押して、差分表示を終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新しい機能を試す

コードがよさそうでも、実際に動くか確認しましょう。前と同じようにアプリを起動し、Codespaces の転送ポートからサイトを開きます。

1. Copilot にアプリの起動を依頼します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. カテゴリによるフィルタリング、発行者によるフィルタリング、計画で合意した組み合わせを試します。
4. リセットと結果が空の場合の動作が、issue と合意事項に沿っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを停止するよう Copilot に依頼します。
